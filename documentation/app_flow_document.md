# App Flow Document

## Onboarding and Sign-In/Sign-Up

A brand new visitor arrives at the application by navigating to the root URL in their browser or by following a shared link. The landing page immediately renders a hero section that adapts based on the user’s authentication status. If the visitor is not signed in, the hero section presents prominent calls to action for signing in or signing up. The user can click the Sign Up button to go to the sign up page, which offers fields to enter an email address and password. Upon submitting valid credentials the user account is created securely by the Better Auth library, and the new user is redirected to the protected dashboard. If the user already has an account, they can click the Sign In button instead and provide their email and password on the sign in page. A lost password link on that page leads to a password recovery flow where the user enters their email address, receives a reset link by email, and follows that link to set a new password. Once the password is reset successfully, the user returns to the sign in page and logs in with their updated credentials. At any point after authentication, the user can choose to sign out by using the Log Out option in the profile dropdown, which ends the session and returns them to the landing page.

## Main Dashboard or Home Page

After a successful login the user lands on the main dashboard, a protected page that requires a valid session. The dashboard view displays a persistent header containing the application logo, a theme toggle control for switching between light mode and dark mode, and a profile dropdown that shows the user’s name and avatar. Alongside the header, a sidebar or navigation menu lists key areas of the app such as Home, Profile, and Settings. The main content area welcomes the user by name and surfaces personalized widgets or a quick overview of recent activity. From the dashboard the user can immediately access other sections of the app by clicking the sidebar links or by using the profile dropdown to navigate to account-specific pages.

## Detailed Feature Flows and Page Transitions

When the user visits the landing page at any time, the server component checks for an existing session via the authentication helper in lib/auth.ts. If no session is found the server renders a guest hero variant that invites the user to sign up or sign in, and if a valid session exists the server renders a personalized hero variant that greets the user and suggests visiting the dashboard. Clicking either the Sign Up or Sign In button on the hero transitions the user to the corresponding authentication page, where Better Auth handles the form submission. After signing in or signing up successfully the user is routed to the dashboard. Within the dashboard, selecting the Profile link in the sidebar or dropdown navigates the user to a profile page where they can see their account details. This profile page shows fields such as full name and email and provides a Save button to update these values. After saving changes the user remains on the profile page and sees a confirmation message indicating that their information has been updated. Choosing the Settings link from the navigation takes the user to a settings page where they can configure preferences such as theme mode and optional notification settings. Making changes on this page and clicking Save applies the updates immediately and displays a confirmation. From any of these protected pages the user can return to the main dashboard by clicking the Home link in the navigation or by clicking the application logo in the header.

## Settings and Account Management

Users manage their account and application preferences on the dedicated settings page. Once on the settings page the user sees options for personal information, theme selection, and notification preferences. The personal information section allows editing of display name and email address, with fields prefilled with current values. The theme selection section offers toggles for light mode, dark mode, or system default. If email notifications are supported, the user can turn them on or off by flipping a switch. After making any adjustments the user clicks the Save button to persist settings. On successful save a confirmation message appears. Users may also update their password by navigating to a change password subsection of the settings page. Here they provide their current password followed by a new password and confirmation. Submitting these fields triggers the Better Auth logic to securely update the password. After completing any settings changes the user can return to the dashboard or navigate to other parts of the application through the sidebar or header controls.

## Error States and Alternate Paths

If a user submits invalid data on any form, such as an email address in the wrong format or a password that does not meet criteria, the form displays inline error messages under the relevant fields. During sign in or sign up, entering incorrect credentials prompts a clear error message at the top of the form explaining the issue. If the application loses connectivity, a banner appears at the top of the page informing the user that the network request failed and suggesting they check their connection. If a user tries to access a protected route without a valid session, the server redirects them to the sign in page and shows a message that they must sign in first. If a password reset link has expired or is invalid, the reset page displays an error page explaining that the link is no longer valid and provides a button to return to the lost password form. All error states guide the user back into a healthy flow, either by reloading the current page, redirecting to the correct form, or offering a retry option.

## Conclusion and Overall App Journey

From the first visit at the landing page through account creation, first login, and everyday use of the dashboard, the application guides the user with smooth transitions and clear feedback. A new user starts by signing up and is immediately welcomed into a personalized dashboard. Returning users experience a dynamic hero that recognizes their session and invites them onward. Throughout the journey users can manage their information, adjust preferences, and recover from errors without confusion. The combination of secure authentication, a modern component library, and server-side rendering ensures that each step feels fast, reliable, and tailored to the individual’s needs. With sign out available at any point, users always have control over ending their session and returning to the public view of the app.
